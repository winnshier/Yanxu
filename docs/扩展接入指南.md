# 扩展接入指南

Yanxu 将 Role、Skill 和 MCP 分开管理：Role 定义责任与基础指令，Skill/MCP 定义可装载能力，AI 人员绑定 Role、CLI、模型、权限与默认能力偏好。导入扩展不会自动新增流程节点。

## 支持的来源

- 本机 OpenCode/Claude Code/通用 Agent 标准目录只读发现。
- 本地目录。
- 公开 GitHub 仓库或子目录。
- Skill 可从 ZIP 导入；Role 一期使用本地目录或 GitHub。

## Skill

Skill 目录以 `SKILL.md` 为入口，可包含引用文档、模板和脚本。导入阶段只读取与扫描，不执行第三方脚本。审查页会展示来源、版本、内容哈希、许可证、脚本、可执行文件、网络主机、工具权限和凭据引用。包含明文敏感信息时阻断安装。

安装后能力仍需要：

1. 在具体项目显式启用。
2. 在计划的具体 WorkUnit 中装载。
3. 在用户确认后冻结版本和哈希。
4. 仅投影到该任务的隔离 CLI 配置，不改写用户全局配置。

## MCP

Yanxu 会区分“用户已经在本机 CLI 中配置的凭据”和“第三方扩展文件携带的明文凭据”：

- 从 OpenCode/Claude Code 标准配置位置发现的 MCP，可以继续使用原 CLI 配置中的本地凭据。扫描时只生成稳定引用；安装、项目能力锁、RuntimeSnapshot 和日志都不保存原值。任务启动时才从原配置解析当前值，并通过只属于该任务 CLI 子进程的临时环境变量注入。
- 环境变量形式支持 OpenCode 的 `{env:NAME}`、Claude 常用的 `${NAME}`，也兼容 `$NAME`。引用的变量不存在时，任务在执行前阻塞并说明缺少项。
- GitHub、ZIP、Skill/Role 扩展文件中的 token、密码或私钥仍视为不安全来源并阻断安装，不能借“本地运行”绕过第三方扩展审查。

Yanxu 分别展示配置解析状态、命令存在状态和运行健康；只有参与当前 WorkUnit 的 MCP 工具才会进入任务权限清单。

## Role

Yanxu 可识别 Claude 子代理、OpenCode Agent、GitHub Agent Profile、纯 Markdown 角色和项目级指令文件。项目级 `AGENTS.md`/`CLAUDE.md` 默认只供查看，避免把整个项目规则误转换为一名人员。

导入的 Role 先进入草稿，确认责任、指令、权限声明、兼容 CLI 和 Skill/MCP 依赖后才可安装。依赖能力独立进入能力中心，不随 Role 自动启用。

## 更新与运行中任务

相同来源再次导入会产生新草稿和差异预览。用户审查后才替换已安装版本。已确认任务使用 RuntimeSnapshot 中的 Role/能力内容哈希，不会被后续更新修改。

## 安全建议

- 优先使用可回溯的 Git commit/tag，不把浮动分支名当作稳定版本。
- 先阅读指令与脚本，再安装；“来自 GitHub”不代表可信。
- 不把部署、`git push`、`sudo` 或高风险删除写成默认权限。
- 先在低风险项目和只读 WorkUnit 中验证新扩展，再用于写入任务。
