# 旧任务兼容层清查与清理记录

更新日期：2026-08-10  
结论：Yanxu 业务层只保留一套 WorkUnit 流程，不再维护 SkillStep 与 WorkUnit 双流程。

## 1. 本次删除

- 删除 `TaskFlowVersion`、`TaskStepKind`、`SkillDefinition`、固定 Skill 结果契约等领域类型。
- 删除任务、计划和运行快照中的 `flowVersion`、`kind`、`preApprovalSkillIds`、`skills` 等双流程字段。
- 删除 `RUN_SKILL_STEP` Job、固定 Skill 执行分支、Skill 专用 Prompt、Schema、结果校验和失败分类。
- 删除 Role 对固定 Skill 列表的绑定，以及团队按 Role/Skill 覆盖率决定能否执行的逻辑。
- 删除内置固定执行 Skill 列表和默认 Skill 序列。
- 删除任务详情页的 Skill/WorkUnit 条件渲染、Skill 执行链标题和旧问题表单兜底。
- 删除 AI 团队页“旧版 Skill 库”入口及 `/api/builtins` 的旧 Skill 返回类型。
- 删除 v1/legacy 兼容测试、Skill 契约测试和固定步骤 ID 驱动的断言。

## 2. 本次统一调整

- 计划协调器只生成 WorkUnit；每个单元由目标、人员、目录、读写模式、所需能力和验证方式组成。
- 需求规格是协调器可选生成的前置文档，不再伪装成 `requirement-specification` Skill。
- 执行结果统一为 `WorkUnitResult`；没有显式文档产物时，系统生成通用结果证据，不要求匹配固定 Artifact 类型。
- 质量门禁从任意 WorkUnit Artifact 的 `metadata.qualityGates` 读取，不依赖 `test-design` 固定步骤。
- 质量失败回退到最近一个成功的可写 WorkUnit；评审整改回退依据读写边界和独立会话标记，不依赖 `implementation` 或 `delivery-review` ID。
- 评审发现从通用 `findings` 证据汇总；自检证据统一命名为 `verificationChecks`，不再使用 Skill CompletionCheck 语义。
- 恢复、重试和门禁推进只判断任务状态、WorkUnit 状态、读写模式与独立会话边界。

## 3. 明确保留，但不属于旧任务兼容

- 外部 Skill 和 MCP：继续作为 Capability 被发现、审查、锁定和按任务装载；它们不参与状态机。
- RoleTemplate：继续定义职责、基础指令和默认推荐能力；不拥有流程步骤。
- Artifact、Session、Gate、Diff、交付报告：作为通用执行证据保留。
- TaskVersion、PlanVersion、知识 supersedes：作为项目记忆和纠错链保留，旧版本退出当前检索但不会被伪装成“正确经验”。
- ProjectSpace Git 历史：用于追溯项目认知、需求、计划和知识如何变化，不用于恢复旧 SkillStep 流程。

## 4. 数据库物理字段

数据库 schema v27 已完成物理收口：

- 删除 `tasks.flow_version`。
- 删除 `task_steps.unit_kind`。
- 将 `task_steps.skill_id` 重命名为 `unit_key`。
- 将 `artifact_versions.skill_id` 重命名为 `unit_key`。
- 删除遗留 `RUN_SKILL_STEP` Job。

运行时代码、测试数据库和新初始化数据库都只使用新列；本机旧数据库按用户决定直接删除并从零初始化，不保留历史任务数据。

## 5. 验证口径

- 源码扫描不得出现 `flowVersion`、`legacy_skill`、`RUN_SKILL_STEP`、`SkillResult`、`preApprovalSkillIds`、`step.kind` 或“旧版 Skill 库”。
- 核心调度不得根据固定 `implementation`、`test-design`、`delivery-review` 等 ID 决定推进、回退或质量结论。
- 外部 Capability 相关的 `skill`、`Skill(...)`、Skill/MCP 导入与运行投影属于保留能力，不能因关键词相同误删。
- 全量 typecheck、自动测试和生产构建必须通过。
