# 迁移与恢复

Yanxu 的恢复分为两层：SQLite 保存流转状态，ProjectSpace 保存需求、计划、产物、交付和知识的可版本化事实。用户关联的代码/文档目录不会被备份到 ProjectSpace；任务变更由 Git 分支和 worktree 保留。

## 自动升级恢复点

当旧 Schema 需要升级时，恢复点位于：

```text
~/.yanxu/system/migration-backups/
```

恢复点记录升级前的完整 SQLite 快照、起止 Schema 版本和创建时间。设置页可查看最近恢复点路径。

## 回滚数据库

```bash
./yanxu db-backups
./yanxu restore-db migration-v22-to-v23-....db
./yanxu
```

恢复前启动脚本会验证并停止已确认的 Yanxu Daemon，对恢复源执行 SQLite `quick_check`，并先把当前数据库保存为 `before-manual-restore-*.db`。恢复后重新运行 `./yanxu`，当前版本会重新应用必要迁移。

## ProjectSpace 重建

如果 SQLite 丢失但项目 ProjectSpace 仍在，从项目页选择 ProjectSpace 并先执行预演。只有哈希、Schema 和必要产物校验可接受时才执行重建。任务、计划、证据和知识可恢复；丢失的 CLI 进程和 worktree 运行现场不会伪装成仍在运行，对应任务会安全转为 `STOPPED`。

## 恢复后检查

- 设置页 SQLite `quick_check` 为 `ok`。
- Schema 当前版本与最新版本一致。
- 项目目录、ProjectSpace 完整性和任务分支可查。
- 重新检测执行 CLI 和 MCP 凭据；恢复点不会复制用户全局 CLI 授权。
- 暂停或停止的任务核对 RuntimeSnapshot 后再恢复。
