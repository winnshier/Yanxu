# 研序 Yanxu vNext 研发版本计划

更新日期：2026-08-06  
计划状态：0.2.0 已完成；0.3.0、0.4.0、0.5.0 与 1.0.0 开发已收口，等待本机真实 CLI 与多项目人工验收  
需求依据：[Yanxu vNext 产品重构需求文档](./Yanxu-vNext产品重构需求文档.md)  
当前版本基线：1.0.0  

## 1. 计划目标

本计划用于明确 Yanxu 从当前 SkillStep 编排模式调整为本地 AI Agent 工程控制面的版本顺序。

计划只划分版本目标、主要功能和验收门槛，不展开接口、数据表、页面组件或开发任务。每个版本完成后必须形成可独立验证的产品增量，不能只完成底层结构而无法运行真实任务。

## 2. 总体版本路线

| 版本 | 版本主题 | 主要结果 |
| --- | --- | --- |
| 0.2.0 | 执行主线回正 | 使用 OpenCode 跑通 WorkUnit、Session 延续、真实门禁和定点修复的新流程 |
| 0.3.0 | 统一能力中心 | 统一发现、管理、锁定并按任务装载 Skill/MCP |
| 0.4.0 | Claude Code 与外部角色 | 开放 Claude Code 执行，支持常见 GitHub 角色转换与导入 |
| 0.5.0 | 双 CLI 统一与生态收口 | 统一 OpenCode、Claude Code 的运行标准并完成扩展能力收口 |
| 1.0.0 | 稳定发布 | 完成迁移、可靠性、安全、体验和真实项目验收，形成可长期使用版本 |

版本按顺序推进。0.2.0 没有通过真实任务验收前，不开始扩建能力生态；0.3.0 没有解决任务级能力隔离前，不开放大规模外部角色和双 CLI 执行。

## 3. 0.2.0：执行主线回正

### 当前实施状态（2026-08-06）

- 已完成新旧流程版本标识与数据库迁移；新任务默认使用 WorkUnit，历史 SkillStep 计划保持兼容读取和执行。
- 已完成 WorkUnit 计划结构、团队候选池分配、自由能力描述、读写边界、验证点和独立会话标记。
- 已解除新任务对 Role/Skill 覆盖率的硬校验；Skill 库仅作为旧流程兼容入口展示。
- 已完成 OpenCode 同一人员 Session 延续、权限规则刷新、失效 Session 自动回退和外部中断联动。
- 已完成跨人员 WorkUnit 结果交接；后序人员可获得前序总结、问题、假设、检查结果和评审发现，不依赖固定 Artifact 或同一 CLI Session。
- 已完成可写 WorkUnit 的真实 Git 变更校验、独立质量门禁、失败证据回传和失败写入单元定点重试。
- 已完成任务、团队、计划确认和执行详情页面的 WorkUnit 语义调整。
- 自动回归已覆盖 v2 新流程、v1 兼容、Session 延续、门禁重试、暂停恢复、并行隔离、交付和恢复；真实 OpenCode 服务启动、健康检查和会话中断已通过。
- 发布门槛中仍待人工完成：选择真实模型跑通一个实际功能任务、制造一次真实门禁失败并确认原 Session 定点修复、并行运行两个真实任务后完成最终产品验收。

### 版本目标

把 Yanxu 从固定 Role/Skill/Artifact 契约驱动的流程，调整为由 WorkUnit、CLI Session 和客观质量门禁驱动的最小可靠闭环。

### 主要功能

- 新任务使用 WorkUnit，不再生成固定 SkillStep 序列。
- 计划围绕目标、范围、工作单元、人员、能力需求、权限、分支和验证方式生成。
- 解除 Skill 与唯一 Role 的绑定；团队改为 AI 人员候选池，不再检查是否覆盖全部内置 Skill。
- 计划确认时推荐实际参与人员，允许团队只使用部分成员。
- OpenCode 作为本版本唯一真实执行适配器。
- 同一人员连续工作时延续原 CLI Session，减少重复阅读和上下文损失。
- 质量门禁失败时将真实失败证据返回原 Session，只修复当前失败工作单元。
- 质量裁决只认真实命令、退出码和日志，不允许模型自报成功覆盖失败。
- 保留现有 Git worktree 隔离、并行任务、暂停、停止、恢复、权限、日志、诊断、交付和项目记忆。
- 新旧流程增加版本标识；历史 SkillStep 任务保持读取、恢复和必要执行兼容，但不再获得新流程功能。
- 调度台、计划确认页和任务详情页改为展示 WorkUnit、Session、系统验证和失败原因。

### 本版本不做

- 不建设第三方扩展市场。
- 不开放 Claude Code 真实执行；Codex 不在当前主线版本范围内。
- 不实现复杂的同一任务内部并行依赖图。
- 不要求完成统一 Skill/MCP 导入，只保留后续接入所需边界。

### 发布门槛

- 一个真实 OpenCode 功能任务能够完成计划确认、执行、门禁、交付和归档。
- 至少一次真实门禁失败能够返回原 Session 修复，且不从任务开头重跑。
- 两个任务可以在同一项目并行，工作区、Session 和结果互不覆盖。
- 团队缺少非必要测试或评审角色时，不会被错误阻止。
- 一期历史任务和 ProjectSpace 数据保持可读、可恢复。

## 4. 0.3.0：统一能力中心

### 版本目标

建立 Yanxu 自己的能力事实源，让 Skill/MCP 可以从本机和外部来源被发现、审查、锁定，并安全装载到项目和任务。

### 主要功能

- 建立统一 Capability Registry，第一阶段管理 Skill 和 MCP。
- 只读扫描 OpenCode、Claude Code 已有的标准 Skill/MCP 配置。
- 区分已发现、已导入、已安装、项目已启用和任务已装载状态。
- 新增能力中心和项目能力配置页面。
- 支持项目启用能力并在 ProjectSpace 中保存版本锁定信息。
- 计划能够声明能力需求，为兼容的 AI 人员临时装载能力，而不是强制新增角色。
- 任务确认后把实际能力版本冻结进 RuntimeSnapshot。
- Skill/MCP 按 CLI 原生格式投影到任务隔离环境，不通过全局配置切换影响并行任务。
- 支持从 GitHub 地址、本地目录和 ZIP 导入标准 Skill。
- MCP 支持统一配置、CLI 格式转换、本地凭据引用和基础健康状态区分。
- 外部扩展导入前展示脚本、依赖、网络、权限、来源、版本和许可证，扫描期间不执行第三方脚本。
- 能力启停、装载和更新进入审计记录。

### 本版本不做

- 不做完整外部角色格式转换。
- 不做扩展市场、评分、发布和社区团队包。
- 不新增真实执行 CLI，任务执行仍以 OpenCode 为主。

### 发布门槛

- 能够发现至少两种本地 CLI 中已有的 Skill/MCP，并明确展示来源和兼容性。
- 能够从 GitHub 或本地目录导入一个标准 Skill，固定版本并启用到项目。
- 任务可以给现有研发人员临时装载该 Skill，并在运行快照和交付证据中追溯版本。
- 两个并行任务使用不同能力配置时互不污染。
- MCP 配置可解析、命令存在和运行健康被分别展示，不产生误导状态。

### 当前实现与验收状态（2026-08-06）

- [x] Capability Registry、数据库迁移和 ProjectSpace 状态重建已完成。
- [x] OpenCode、Claude Code 与通用 Agent 标准 Skill/MCP 只读发现已完成；单个来源错误会聚合展示。
- [x] 已发现、已导入、已安装、项目启用、任务冻结/投影状态已分层实现。
- [x] 本地目录、ZIP、公开 GitHub 仓库/子目录导入已完成；导入阶段不执行第三方脚本，明文凭据和敏感文件会阻断安装。
- [x] 能力审查页展示来源、版本、哈希、许可证、文件、脚本、可执行文件、网络主机、工具权限、元数据和凭据引用。
- [x] 项目能力锁、计划按 WorkUnit 选择、RuntimeSnapshot 冻结和交付报告追溯已完成。
- [x] OpenCode 任务独立配置投影、未选 Skill/MCP 禁用和并行任务隔离已完成。
- [x] 自动化类型检查、Lint、55+ 核心回归、Daemon/Web 测试和生产构建已通过；独立临时 Daemon、首页主资源及能力中心动态分包冒烟通过。
- [ ] 使用用户真实 OpenCode 配置选择一个本机 Skill/MCP，完成一次从计划确认到交付的人工验收。

## 5. 0.4.0：Claude Code 与外部角色

### 当前实现与验收状态（2026-08-06）

- [x] Claude Code 非交互结构化输出、独立/恢复 Session、终止、超时、原始日志和本地 Schema 二次校验已接入统一 ExecutorAdapter。
- [x] Scheduler 可按 WorkUnit 人员选择 OpenCode 或 Claude Code；跨 CLI 步骤会关闭旧 Runtime，两者共用任务状态、ContextPack、Git 证据、门禁和交付标准。
- [x] Claude Code 使用 `dontAsk` 与任务级 allow/deny 规则执行，严格使用本任务 MCP 配置；未规划动作不能通过后台权限提示绕过 Yanxu。
- [x] 能力投影支持 Claude 项目 Skill 和严格 MCP 配置，不改写用户全局 CLI 配置。
- [x] 支持本地目录和公开 GitHub 角色仓库；可识别 Claude 子代理、OpenCode Agent、GitHub Agent Profile、纯提示词角色和项目级指令文件。
- [x] 外部角色先进入草稿，展示职责、基础指令、权限、依赖能力、兼容 CLI、来源、版本和哈希；不可转换内容明确标记仅查看/不兼容。
- [x] 外部角色审查安装后可创建人员；依赖 Skill/MCP 独立进入能力中心，不随角色自动启用。
- [x] 相同来源内容更新会保留历史版本、重新进入草稿，并提供字段与基础指令变化预览；运行快照保留任务确认时版本。
- [x] 类型检查、Claude 进程契约测试、角色格式/审查测试、核心回归和 Daemon 回归已通过。
- [ ] 当前开发机未安装 `claude` 命令；安装并完成一个真实 Claude Code 需求闭环后，才能把真实执行发布门槛标记为通过。

### 版本目标

在统一执行和能力体系已经稳定的前提下，开放 Claude Code，并让 GitHub 中常见的优秀角色定义可以快速进入 Yanxu。

### 主要功能

- 完成 Claude Code CLI 的真实任务执行适配。
- Claude Code 支持独立 Session、暂停、停止、恢复、日志、权限、失败反馈和质量门禁闭环。
- OpenCode 与 Claude Code 使用统一的任务状态、证据和交付标准。
- 支持识别常见 Claude Code、OpenCode 角色定义和纯提示词角色。
- 外部角色导入后生成可审查的 RoleTemplate 草稿，不直接激活。
- 导入时展示角色职责、基础指令、依赖 Skill/MCP、权限、兼容 CLI、来源和版本。
- 用户确认角色使用的 CLI、模型、权限和默认能力后，可以创建 AI 人员并加入团队。
- 无法可靠转换的角色明确标记为不兼容或仅供查看。
- 外部角色依赖的 Skill/MCP 作为独立能力导入，不与角色形成不可拆分绑定。
- 支持扩展版本检查和变更预览，更新不影响运行中任务。

### 本版本不做

- 不开放 Codex CLI 真实执行。
- 不做一键导入后未经审查自动运行。
- 不做角色评分、在线市场和自动推荐社区内容。

### 发布门槛

- 同一个真实需求可以分别使用 OpenCode 和 Claude Code 完成，并产生同标准证据。
- Claude Code 任务能够暂停、恢复，并在门禁失败后继续原任务修复。
- 能够从一个真实 GitHub 仓库识别角色和依赖 Skill，生成可审查草稿并加入团队。
- 外部角色不能绕过 Yanxu 的任务权限和能力审查。

## 6. 0.5.0：双 CLI 统一与生态收口

### 当前实施与验收状态（2026-08-06）

- [x] OpenCode 和 Claude Code 已统一到 WorkUnit、ContextPack、Git 证据、失败重试、质量门禁和交付模型。
- [x] AI 人员支持绑定 CLI、模型、Role 和默认 Skill/MCP；默认能力只是规划偏好，项目未启用或 CLI 不兼容时明确提示。
- [x] 同一团队可组合 OpenCode 和 Claude Code 人员，不强制多 CLI 参与；独立评审可使用不同 CLI 与独立 Session。
- [x] RuntimeSnapshot 已冻结任务所用 CLI 版本、路径哈希、能力和模型；恢复运行前会记录环境漂移并拒绝缺少必要能力的执行器。
- [x] 两种 CLI 已共用任务状态、暂停/恢复/终止语义、权限事件、统一 Runtime 日志和运行诊断页。
- [x] Role/Skill 重新导入会进入新草稿，保留版本历史与差异审查；运行中任务继续使用确认时快照。
- [x] 自动化覆盖双 CLI 团队快照、独立评审边界、执行器契约和新旧流程回归。
- [ ] 当前开发机未安装 `claude` 命令；真实 OpenCode、Claude Code 双 CLI 任务和跨 CLI 独立评审仍需人工验收。

### 版本目标

在 OpenCode 和 Claude Code 都能独立完成真实任务后，统一两种执行器的产品行为，并验证角色、团队和能力可以跨 CLI 组合。

### 主要功能

- OpenCode 和 Claude Code 使用统一的 WorkUnit、RuntimeSnapshot、失败分类、门禁和交付证据。
- 创建 AI 人员时能够基于 CLI 实际能力选择兼容的角色、模型、Skill 和 MCP。
- 计划分配能够在已选团队中选择不同 CLI 人员，但不强制多 CLI 同时参与。
- 需要责任隔离时，支持开发和独立评审使用不同 CLI Session。
- 完善两种 CLI 的能力投影、兼容性检查、缺失能力提示和降级说明。
- 完善扩展更新、差异审查、版本锁定和历史任务版本保留。
- 统一两种 CLI 在暂停恢复、权限事件、日志展示和错误诊断上的用户体验。

### 本版本不做

- 不自动判断哪种模型“绝对最好”。
- 不引入复杂成本调度、自动竞价或多个 Agent 同时修改同一工作单元。
- 不做远程执行集群或云端账号系统。
- 不接入 Codex 或其他新执行器；本版本只收口 OpenCode 与 Claude Code。

### 发布门槛

- OpenCode、Claude Code 分别完成至少一个真实研发任务闭环。
- 同一团队可以包含不同 CLI 人员，计划能够按兼容能力分配而不依赖固定角色流程。
- 独立评审可以使用不同 CLI，并且不会复用开发 Session。
- 两种 CLI 的任务都能使用统一诊断、质量门禁、交付和历史证据页面。

## 7. 1.0.0：稳定发布

### 当前实施与验收状态（2026-08-06）

- [x] 数据库在已有 Schema 升级前自动创建经 `quick_check` 验证的恢复点；支持列出恢复点和停止 Daemon 后安全回滚，回滚前再保留当前数据库。
- [x] 旧应用会拒绝打开未来 Schema 或迁移链缺失的数据库，避免静默降级破坏。
- [x] 健康检查和设置诊断已展示应用版本、当前/最新 Schema、日志大小和最近迁移恢复点。
- [x] 启动脚本已统一旧 Daemon 验证停止、依赖/原生模块检查、构建和新版本启动；未验证进程不会被误杀。
- [x] Daemon 和 CLI Runtime 日志已有大小边界与保留代数，OpenCode Runtime 进程结束会关闭日志句柄。
- [x] 安装升级、迁移恢复、故障排查和扩展接入公开文档已补齐。
- [x] TypeScript、Lint、Web/Executor/Core/Daemon 自动回归和生产构建已通过；数据库升级恢复点与手工回滚命令有端到端测试。
- [x] 本机 OpenCode 1.17.15 的真实 `serve`、SDK 健康、Session 创建与中止契约已通过；本次未调用付费模型。
- [ ] 当前开发机未安装 `claude` 命令，真实 Claude Code 闭环尚未完成。
- [ ] 多个真实项目、空项目、文档项目、多仓库与全新 clone 的最终人工验收仍未完成；在此之前不宣称 1.0 发布门槛全部通过。

### 版本目标

将 vNext 从可用功能集合收口为可长期使用、可升级、可诊断和可公开发布的本地产品。

### 主要功能

- 完成一期数据到 vNext 的安全迁移、预演、失败回滚和历史只读兼容。
- 完成 ProjectSpace、能力锁定清单、RuntimeSnapshot 和数据库恢复验证。
- 统一处理 CLI 升级、配置变化、模型不可用、能力失效和 MCP 凭据缺失。
- 完善启动脚本、一键运行、Daemon 单实例、版本一致性和升级提示。
- 完成任务看板、计划确认、能力中心、团队、执行诊断和交付页面的整体体验收口。
- 完成安全审计、权限边界、第三方扩展隔离、敏感信息和本地凭据保护。
- 完成长时间任务、并行任务、日志体量、项目索引和能力扫描的性能与稳定性优化。
- 建立公开安装、使用、迁移、故障排查和扩展接入文档。
- 使用多个真实项目完成产品研发、文档项目、新建空项目和多仓库项目验收。

### 1.0 不包含

- 扩展市场、评分和商业分发。
- 云端同步、远程执行和多人协作账号。
- 同一任务内部的大规模并行 Agent 图。
- 自动部署、远程推送和无人审批的高风险外部操作。

### 发布门槛

- OpenCode 与 Claude Code 的核心流程均通过自动测试和真实任务验证。
- 安装、升级、迁移、恢复和卸载不会破坏用户项目与历史证据。
- 模型自报、第三方扩展或单个 CLI 故障不能绕过质量与安全边界。
- 用户能够从页面理解任务当前状态、失败原因、系统动作和最终交付依据。
- 全新 clone 后能够一键启动并完成首个真实任务。

## 8. 跨版本研发约束

- 每个版本只围绕一个主要产品目标收口，不在未通过真实验收前继续横向扩展。
- 所有新任务使用新流程；旧流程只维护历史读取和必要恢复，不继续新增功能。
- 每个版本必须同时完成后端能力、用户可见页面、自动验证和真实场景验收。
- 不能用 Fake Executor、模型结构化输出或页面存在代替真实 CLI 任务验证。
- 任何版本都必须保持 ProjectSpace、Git 工作区和历史任务数据兼容。
- 新增能力不能进入固定状态机；新增角色不能自动增加流程节点。
- 版本发布后再更新下一版本实施计划，避免一次性把全部细节写死。

## 9. 1.0 之后再评估

以下方向保留，但不进入当前研发承诺：

- Codex CLI 作为 OpenCode、Claude Code 稳定后的下一执行适配器。
- 其他本地编码 CLI 的持续适配。
- Skill、角色和团队模板市场。
- 扩展评分、签名、发布和社区治理。
- 云端同步与多设备共享。
- 远程执行节点和团队协作。
- 同一任务内部多 Agent 并行依赖图。
- 成本预算、模型自动竞价和基于历史效果的智能路由。
- 自动创建远程 PR、部署和生产环境操作。
