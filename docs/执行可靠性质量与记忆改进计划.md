# 研序执行可靠性、质量与记忆改进计划

更新日期：2026-07-30  
当前状态：功能实现完成，回归验收中  
适用范围：一期现有产品研发流程的增量完善，不改变“需求确认后无人值守执行”的产品主线。

## 1. 改进目标

基于已完整运行的两个真实任务，本轮只解决三个已经有事实证据的问题：

1. 质量结论不能只依赖模型的一句 `success`，必须能区分门禁未配置、门禁通过、门禁失败，以及评审问题的严重程度。
2. 执行失败不能全部盲目重试，必须先分类，再决定重试、重新规划或等待人工处理；旧计划、旧步骤和旧任务版本不得在恢复后继续写入。
3. 用户和维护者需要一眼看懂任务为什么慢、为什么重试、最后凭什么交付；项目记忆只沉淀可复用的项目事实，不重复、不把系统故障污染为项目经验。

## 2. 实施顺序与状态

### P0：异常分类、重试决策与版本不变量

- [x] `REL-001` 定义统一失败分类：瞬时故障、模型输出不合法、Skill 契约不满足、权限/范围问题、模型能力不兼容、Git 语义冲突、运行版本过期、系统故障。
- [x] `REL-002` 每次失败记录分类、错误指纹、是否可重试、建议动作、任务/计划/步骤版本和执行轮次。
- [x] `REL-003` 只对瞬时故障和可恢复系统故障自动退避重试；确定性错误直接转重新规划或人工处理。
- [x] `REL-004` 相同错误指纹连续出现时提前停止盲重试，避免重复消耗模型时间。
- [x] `REL-005` Job 领取与结果落库前校验任务状态、TaskVersion、PlanVersion、StepId 和 StepAttempt；旧运行结果只记录为已丢弃证据，不改变当前任务。
- [x] `REL-006` 补齐失败分类、重复错误、旧 Job 和旧 Session 结果的单元/集成测试。

验收标准：同一种确定性错误不会连续调用模型三次；恢复或重规划后，旧计划结果不能推进新计划状态。

### P1：真实质量门禁与结构化评审裁决

- [x] `QUA-001` 门禁汇总显式区分 `not_configured / pending / running / passed / failed / waived`。
- [x] `QUA-002` 未配置门禁时记录“未配置/跳过”，不再生成“质量门禁全部通过”的误导结论。
- [x] `QUA-003` 评审结果增加结构化 Finding：严重级别、类别、证据、定位、建议、是否阻塞交付。
- [x] `QUA-004` 系统按 Finding 和 CompletionCheck 自动裁决：阻塞问题不能被模型用 `success` 覆盖；非阻塞问题可交付但必须进入报告。
- [x] `QUA-005` 交付报告同时展示门禁状态、阻塞问题、非阻塞风险、豁免项及其证据。
- [x] `QUA-006` 保持旧模型 `issues: string[]` 输出兼容，缺少结构化字段时按保守规则归一化。
- [x] `QUA-007` 补齐无门禁、评审有阻塞问题、旧问题字段和仅有非阻塞建议的测试；既有门禁失败回流测试继续保留。

验收标准：页面和报告不会把“0 个门禁”展示为“门禁通过”；评审发现运行错误时任务不能直接交付。

### P1：任务诊断摘要与可观测性

- [x] `OBS-001` 后端按现有 Event、Job、Session、Gate、Recovery 和 ContextPack 聚合任务诊断，不再新造一套运行状态。
- [x] `OBS-002` 诊断摘要展示总耗时、模型执行耗时、等待耗时、会话成功/失败、重试次数、恢复次数、计划版本数、上下文 token 估算与截断次数。
- [x] `OBS-003` 输出失败分类时间线和“为什么进入当前状态”的最近关键决策。
- [x] `OBS-004` 任务详情增加“运行诊断”页签；报告中写入同一份诊断快照。
- [x] `OBS-005` 增加诊断 API、聚合测试和前端渲染测试。

验收标准：出现阻塞或长时间运行时，不查 SQLite 也能从任务详情判断卡在哪一步、失败了几次、系统采取了什么动作。

### P1：高质量项目记忆

- [x] `MEM-001` 知识候选使用内容哈希去重；相同内容不生成新版本、不把旧候选标为 superseded。
- [x] `MEM-002` 交付报告可在 `DELIVERED` 生成，但知识候选只在用户确认归档后生成一次。
- [x] `MEM-003` 决策候选只记录已确认的目标、范围、技术/产品决策及成功标准。
- [x] `MEM-004` 经验候选必须包含“问题—原因—处理—验证—适用边界”；没有可复用证据时不生成经验候选。
- [x] `MEM-005` CLI、模型兼容、Daemon、重试等运行故障只进入任务诊断，不写入项目知识；确实影响项目规范时由用户明确确认后再进入知识。
- [x] `MEM-006` 知识候选记录来源 Artifact、Gate、Review 和 TaskVersion，便于追溯与纠错。
- [ ] `MEM-007` 补齐重复交付/归档、无有效经验、知识修订与 FTS 生效测试。

验收标准：同一任务归档后最多生成一组不重复候选；项目检索上下文不包含与项目无关的系统运行故障。

## 4. 设计约束

- SQLite 继续作为运行状态权威来源；ProjectSpace 继续保存可版本化文档与证据。
- 不引入 LangChain、消息队列或新的工作流框架；本轮扩展现有 Store、Scheduler、Event 和 Job。
- 不让协调模型决定底层重试策略；异常分类和版本不变量由确定性代码裁决。
- 模型负责产出内容和评审判断，系统负责校验格式、证据完整性和能否推进状态。
- 保持历史任务、旧 Skill 输出和现有 API 的向后兼容。

## 5. 完成定义

只有当 `REL-*`、`QUA-*`、`OBS-*`、`MEM-*` 和 `AUTO-*` 均完成后，本轮才标记完成；`HUMAN-*` 由用户在真实任务中最终验收。
