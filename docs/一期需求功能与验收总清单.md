# 研序一期需求、功能与验收总清单

更新日期：2026-07-27  
当前阶段：Codex 负责的实现和自动验收已收口，等待用户验收与真实 OpenCode 模型验证。

本文档是一期唯一有效的实施与验收清单。《完善计划清单》仅保留为历史入口，不再单独判定完成状态。

## 1. 验收边界

### 1.1 Codex 可以独立验证

- 类型、Lint、单元测试、集成测试和生产构建。
- 状态机、任务拆分、失败重试、一次自动重规划、暂停、停止和恢复。
- SQLite 数据、ProjectSpace 文件、Git 分支/worktree、变更清单和完整性。
- HTTP API、本地 Cookie/CSRF、短期文件选择令牌和受控文件读取。
- Fake Executor 下的完整研发流程。
- 空目录初始化、多目录、脏工作区、并行任务、冲突和交付合并。
- React 组件的结构化内容渲染。
- 已构建 Daemon 的本地监听、健康接口、生产首页和本地会话。

### 1.2 必须由用户或真实外部条件验证

- 页面视觉、信息密度、文案和操作是否符合直觉。
- macOS 原生文件/文件夹选择弹窗和系统授权体验。
- 真实 RequirementSpec、ExecutionPlan、代码、测试、评审和交付报告的质量。
- 真实业务语义冲突的最终取舍。
- OpenCode 账号、Provider、余额和模型是否支持 JSON Schema 与权限事件。
- GitHub 提交、推送和全新 clone；这些是仓库发布动作，Codex 未获得提交或推送授权。

### 1.3 一期架构边界

- SQLite 是运行状态、调度、索引和关系数据的权威来源。
- ProjectSpace 保存可版本化的需求、计划、产物、附件、项目认知、知识、报告和状态恢复清单。
- ProjectSpace 使用独立 Git 记录已知文件的版本变化，并拒绝静默提交未知外部文件。
- 一期通过 `PREPARED / succeeded / failed` 操作记录、状态清单、内容哈希和完整性检查保证可诊断恢复；不实现 SQLite、文件系统和 Git 之间的分布式 ACID 事务。
- Directory Profile 先由确定性扫描生成候选，人工确认后生效。任务协调器按任务检索最新项目文件和知识；一期不让 AI 在项目初始化时自动写入长期认知，避免错误认知未经确认进入记忆。

### 2.2 Git、并行与交付

- [x] `GIT-007` 多目录合并失败时补偿已完成的前序合并。
- [x] `GIT-008` 支持“自行合并”和“合并到目标分支”；目标分支合并后重新执行门禁。
- [x] `GIT-009` 交付动作、冲突决定和最终报告进入证据链。

## 6. 明确延期，不属于一期未完成

- Claude Code CLI 和 Codex CLI 执行适配器。
- 从 GitHub/技能市场安装第三方 Role/Skill，并支持 Role 上的 Skill 启停。
- 用户自定义 ProjectSpace 根路径。
- 二进制附件的 PDF/OCR/图片内容提取。
- 容器或虚拟机级执行隔离。
- SQLite、文件系统和 Git 之间的分布式 ACID 事务。
- 浏览器自动点击类 E2E；本轮按约定使用代码、组件、HTTP 和生产服务验证，视觉交互由用户验收。
