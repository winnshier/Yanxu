## 3. 1.1 Run 与恢复

- [x] Task 与单次真实执行 Run 分离。
- [x] 重试创建新 Run，并记录 `retryOfRunId`。
- [x] Session 与 Run 分离，记录新建、复用和失效原因。
- [x] 冻结每个 Run 的步骤、人员、执行器、模型、尝试次数和工作区，不从当前配置反推历史。
- [x] 统一增量记录状态、思考、文本、工具、日志与错误事件；Claude Code 使用 `stream-json`，OpenCode 只写入轮询增量和状态转换。
- [x] 每个 Run 拥有独立 JSONL 事件日志，Runtime 自身日志与任务聚合日志不冒充 Run 证据。
- [x] OpenCode 和 Claude Code 停止整个进程组。
- [x] Daemon 重启、租约超时和孤儿任务将旧 Run 标记为中断，再创建恢复 Run。
- [x] 独立 Run 页面展示事件筛选、时间偏移、失败定位、Session、现场和下一步。
- [x] Run 页面展示本次工作区、精确文件变更清单和本 Run 后产生的确定性质量门禁。
- [ ] 真实 OpenCode 停止/恢复。
- [ ] 真实 Claude Code 停止/恢复。

## 4. 1.2 双 CLI 能力

- [x] 支持 OpenCode 与 Claude Code，不接入 Codex。
- [x] 启动和恢复时检查 CLI 路径、文件哈希、版本、模型和必要能力。
- [x] CLI 重新安装或切换路径后使缓存适配器失效并重新探测。
- [x] “校验 CLI”真实启动所选执行器并调用所选模型完成最小结构化响应，不再只检查二进制和模型列表。

- [x] Skill/MCP 只投影到任务 Runtime，不永久修改用户全局配置。
- [x] 任务能力记录未检查、已装载、已连接、健康、失败、需认证和已禁用等运行状态，并关联最后一次 Run。
- [x] 本机已有凭据只在运行时传递，不复制原始明文到 ProjectSpace。
- [ ] OpenCode 标准 Skill/MCP 真实验收。
- [ ] Claude Code 标准 Skill/MCP 真实验收。

## 5. 1.3 定时触发

- [x] ScheduleDefinition 与 ScheduleOccurrence 独立持久化。
- [x] 支持一次性和按小时、天、周周期触发。
- [x] 每次触发基于当前项目状态创建独立 Task，后续统一进入 Run、门禁和交付。
- [x] 支持仅报告、发现后创建任务和已确认边界内自动执行。
- [x] 发现模式先运行只读检查；无发现直接形成报告，有发现则修订同一任务并回到计划确认，确认后继续执行。
- [x] 自动化边界冻结计划摘要、人员/模型、能力版本、门禁、目录、分支、权限、网络和依赖策略；漂移时创建新计划并等待确认。
- [x] 支持时区、休眠补跑一次或跳过、重叠合并为一个待执行机会或跳过。
- [x] 编辑定时定义时，非时间字段修改保留下一次触发；时间规则修改重新计算并跳过旧的未执行触发。
- [x] Daemon 恢复时回收中断 Occurrence，幂等键避免重复创建。
- [x] 自动执行只到待交付，不自动合并、推送或部署。
- [ ] 真实时间等待、休眠和重启场景验收。

## 8. 当前没有宣称完成的部分

- 自动测试不能证明本机 OpenCode 和 Claude Code 的账号、模型、Thinking、Skill 与 MCP 都真实可用。
- 生产构建成功不能替代 macOS 常用窗口宽度下的逐页视觉检查。
- Git 单元测试和模拟 E2E 不能替代用户真实多仓库、真实脏工作区和真实语义冲突验收。
- 定时调度单元测试不能替代一次真实休眠、唤醒和 Daemon 重启验证。
